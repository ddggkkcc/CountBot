## 问题描述

切换技能后(修改技能内容、启用/禁用技能、或切换工作区导致技能目录变化),在**同一会话**中再次提出与技能相关的问题时:

1. Agent 不重新 `read_file` 读取最新技能,而是直接复用历史对话中残留的**旧技能内容**作答("糊弄");
2. 当技能不存在/不可用时,Agent 不直接说"找不到",而是反复调用工具(memory_search / read_file)形成**死循环**,直到触发最大迭代次数后自行退出;
3. 记忆搜索按 OR 模式返回的**弱相关条目**会被当作答案依据使用("从记忆捞了没用的回来"),用户无法接受。

**核心诉求**:找不到就说找不到,用户能接受;但编造内容、用旧上下文/无关记忆凑数,不能接受。死循环和迭代上限本身不是主要问题。

## 复现步骤

1. 在会话中使用技能 X(Agent 通过 `read_file` 读取了 `skills/X/SKILL.md` 并按其执行);
2. 修改技能 X 的 `SKILL.md` 内容,或禁用技能 X,或切换工作区(技能目录随之 reload);
3. 在同一个会话中,继续提出与技能 X 相关的同一个问题;
4. 观察回复:Agent 直接复用第 1 步读到的旧技能内容作答,未重新 `read_file`;若技能已被删除/禁用,则反复调用 `read_file` / `memory_search`,最终输出 `[达到最大迭代次数 25]` 自行退出,或给出编造的内容。

## 期望行为

- 技能目录/内容发生变化后,历史对话中的技能内容一律失效;Agent 应先重新 `read_file` 读取最新技能内容再作答;
- 技能不存在或不可用时,如实告知用户"找不到/不可用",禁止编造、禁止用历史或记忆中的无关内容凑数;
- 重复失败场景应提前体面收场,而不是死循环烧满迭代上限。

## 实际行为

- 直接拿历史上下文中的旧 SKILL.md 内容作答(不重新读取);
- 找不到技能时反复调用工具形成循环,直至 `[达到最大迭代次数 25]` 自行退出;
- 记忆搜索 OR 模式返回单关键词弱命中的无关条目,被当作答案依据使用。

## 附加信息

初步根因分析(供开发参考,**方案尚未实施**):

1. **历史污染**:会话历史从数据库原样加载(`backend/modules/session/context_service.py` 的 `build_model_context` / `default_message_formatter`),包括此前 `read_file` 读到的 SKILL.md 全文(tool 角色消息)。切换技能后旧内容仍完整存在于上下文中,模型走捷径直接复用。system prompt 中的静态规则("禁止凭记忆作答")无法对抗眼前就有的旧内容。
2. **记忆检索门槛过低**:`backend/modules/agent/memory.py` 的 `MemoryStore.search` 为 OR 模式,单关键词弱命中也会返回(目前仅打 `[弱相关]` 标签,依赖模型自觉)。
3. **AgentLoop 无防卡死逻辑**:`backend/modules/agent/loop.py` 主循环无重复工具调用检测,失败后反复重试直到 `max_iterations`,期间可能持续生成编造内容。
4. **溢出总结污染记忆**:`context_service.py` 的自动总结(overflow/整会话)会把引用 SKILL.md 内容的助手回复沉淀进 `MEMORY.md`,旧技能步骤从此进入长期记忆,后续又会被 `memory_search` 搜出来。

建议修复方向:

- **历史净化**:context 进入 LLM 前过滤历史中的 SKILL.md 读取结果(连同对应 assistant tool_calls 消息成对删除,避免 API 校验失败);技能目录指纹(名称+mtime+启用状态)变化时,向 system prompt 注入动态失效警告。
- **记忆检索相关度下限**:OR 模式下弱相关条目默认不返回;零结果/全弱命中时明确输出"未找到相关记忆"。
- **Loop 认输协议**:相同 (tool, 参数) 连续重复 ≥3 次、或技能读取失败时,注入 system 指令"停止重试,找不到就如实告知用户,禁止编造",提前体面收场。
- **溢出总结过滤**:喂给总结 prompt 前剔除引用 SKILL.md 的片段,避免旧技能步骤沉淀进长期记忆。
